# Approved Ion Reference Snapshot

**Source catalog:** `projectReference.md` version 1.1.0 (updated 2026-08-27)
**Status:** Repository-local snapshot; subordinate to the Master Specification,
accepted ADRs, and project-local context.

Presence here is not dependency approval. The cards are process guidance,
future implementation ownership, or deferred reference material only.

## `PROFILE-ION`

**Character:** Calm operational system with one unmistakable Core.
**Preferred references:** Ion Master Specification, `IMPECCABLE`,
`EMIL-MOTION`, `MOTION`, `THREE`; later shader ideas only when permitted.
**Default exclusions:** Decorative shaders behind daily UI, duplicate graphics
runtimes, premature AI, and premature integrations.

## `MANUS`

**Status:** `reference-only`
**Purpose:** Artifact-oriented execution, visible plans, reusable procedures,
failure visibility, progressive skill loading, and explicit parallel-work
synthesis.
**Use:** Architectural inspiration for agent and context engineering.
**Avoid:** Cloud assumptions that conflict with local-first privacy or human
confirmation.
**Source:** <https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus>

## `IMPECCABLE`

**Status:** `preferred`
**Purpose:** Broad design process for hierarchy, accessibility, performance,
and polish.
**Use:** Shape or review an approved surface from user goals and real content.
**Avoid:** Letting generic redesign instructions override accepted decisions.
**Source:** <https://github.com/pbakaus/impeccable>

## `EMIL-MOTION`

**Status:** `preferred`
**Purpose:** Motion opportunity finding, specification, implementation review,
and feel.
**Use:** After product purpose and interaction frequency are known.
**Avoid:** Using motion to compensate for weak hierarchy or unclear content.
**Source:** <https://github.com/emilkowalski/skills>

## `MOTION`

**Status:** `preferred` — future implementation owner, deferred.
**Purpose:** Stateful React UI transitions, layout continuity, gestures, and
presence after CSS.
**Avoid:** Owning a 3D renderer or overlapping with another motion owner.
**Source:** <https://motion.dev/docs/react>

## `THREE`

**Status:** `preferred` — future implementation owner, deferred.
**Purpose:** A justified spatial Ion Core or other signature 3D visual.
**Avoid:** Decorative full-page GPU work, independent continuous canvases, or
inaccessible graph views.
**Source:** <https://threejs.org/docs/>

## `OBSIDIAN`

**Status:** `preferred` — future knowledge reference, deferred.
**Purpose:** Human-editable Markdown, links, properties, and graph exploration.
**Avoid:** Treating the visual graph as the knowledge model.
**Source:** <https://obsidian.md/help/data-storage>

## `LLM-WIKI`

**Status:** `preferred` — future knowledge reference, deferred.
**Purpose:** A maintained layer between immutable sources and repeated queries.
**Use:** Raw sources, schema/rules, ingest/query/lint operations, compiled
Markdown, indexes, and an append-only log; user edits remain authoritative.
**Avoid:** Blurring source evidence and synthesis.
**Source:** <https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f>
